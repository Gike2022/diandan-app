# 商家工作台使用说明

沿用顾客页面的粉紫色、星空和圆角卡片；手机单栏操作，桌面增加显示宽度和卡片列数。

## 进入与登录

保持前后端运行：项目根目录两个终端分别执行 `npm run dev:api` 和 `npm run dev`。打开 <http://127.0.0.1:5173/admin>，使用 `admin` / `Admin12345!` 登录。管理员在顾客首页也能通过左上角商家图标进入工作台。

登录页复用现有认证，成功后返回原管理地址。普通顾客无法进入工作台，服务端也独立校验管理接口权限。右上角可退出，退出或切换账号会清理商家查询缓存；数据库连接信息仍只在被 Git 忽略的 `server/.env`。

## 菜品与分类

- 菜品管理 `/admin/menu`：按名称搜索、按分类筛选、分页查看。点击新增或编辑，填写名称、分类、元单位价格、描述、可选图片地址、排序、售罄与上架状态。金额最多两位小数，范围为 0.01–10000.00 元。
- 图片可从本机上传 JPG/PNG/静态 WebP（单张最多 5 MB），上传后预览，保存菜品后生效；也可继续填写 HTTP/HTTPS 图片地址。不填时管理列表显示占位图标。操作与图片备份见 [扩展功能说明](statistics-images-account-guide.md)。
- “设为售罄”让顾客可见但不能加购；“下架菜品”从顾客菜单隐藏。恢复可售或上架可撤销这些操作，不删除旧订单明细。
- 分类管理 `/admin/categories`：新增、编辑名称和排序、启用或停用。排序越小越靠前。停用分类会隐藏其中全部菜品，菜品管理列表会提示隐藏原因。

保存失败时保留输入并显示错误，成功后刷新管理列表和当前浏览器中的顾客菜单缓存。其他浏览器可刷新菜单获取变更。旧购物车金额是预览，服务端下单时按当前价格和可售状态重新核算；历史订单继续保留下单时快照。

如果另一端在编辑期间更新了菜品或分类，保存会提示“记录已被其他页面修改”，本次输入保留，但不会覆盖另一端的数据。点击取消后重新打开最新记录，再应用自己的修改即可。

新增菜品或分类在网络中断后可能已保存成功，页面会保留这次请求，点击保存安全确认原记录；刷新后重新点击“新增菜品/分类”会恢复待确认内容。待确认时暂时锁定字段，避免修改同一个新增请求造成混淆。

## 接单与进度

订单页 `/admin` 默认显示已付款待接单订单，每 5 秒自动同步，支持手动刷新、状态筛选和分页。卡片展示菜品、数量、包装费、合计、联系人、手机、地址和备注。

输入完整或部分订单号（字母数字，大小写均可），选择开始/结束日期后点击“查询订单”；日期按北京时间的下单日期计算，结束日期包含整天，也可只填写开始或结束日期。订单状态切换即时生效，其余字段点击查询后生效，下方会显示实际应用的条件。查询会回到第一页；没有结果时可修改条件或点击“重置”，恢复默认待接单列表。

订单、菜品、分类三个商家页面均显示“新订单提醒”卡片及待接单数量。顾客成功付款后，每 5 秒检查一次，新付款待接单订单通过弹窗提醒，多笔合并提示；首次进入时已有订单只显示数量。提醒不受当前订单号、日期、状态、分页影响；接走一单又收到一单、总数量不变时也能识别。点击“查看待接单”会进入默认列表并清空查询条件，接单或拒单后数量随即更新。

当前标签页按商家账号保存已同步的待接单快照，因此切页和刷新不会重复弹出同一批提醒。断网时显示同步中断和上次数量，可点“重试提醒同步”；恢复后补查仍然待接单的新订单。保持商家页面和后端运行可持续接收提醒；浏览器后台休眠可能延后同步，回到页面时自动重新查询。

1. 顾客完成模拟付款后，订单进入“待接单”。商家点击“接单并制作”，订单进入“制作中”。
2. 切换到“制作中”，点击“开始配送”，订单进入“配送中”。
3. 切换到“配送中”，点击“确认完成”，可在“已完成”中查询。
4. 无法接单时，点击“拒单并模拟退款”，填写顾客可见原因并确认。订单取消，后端在同一事务记录模拟退款；不会真实退款或扣款。

未付款订单等待顾客付款，商家不能提前接单；已完成或已取消的订单只读。前后端均限制跳级和回退。同一订单被其他终端修改时，失败信息会提示并重新查询真实状态，不把本地按钮点击视为成功。

顾客默认有 15 分钟付款。超时未付款会自动取消，商家在已取消列表中可看到“付款超时自动取消”的原因，不发生模拟退款。已付款订单不因付款时限到期而取消。

处理当前页最后一笔订单导致总页数减少时，自动返回最后一个有效页，避免剩余订单被空分页隐藏。

演示时可在两个浏览器或独立会话中分别登录顾客和商家：顾客下单付款 → 商家接单、配送、完成 → 顾客详情和历史订单自动同步。

## 验证

商家导航新增“营业统计”，展示日期范围内的营业额、单量、每日趋势、状态和热门菜品；页头“个人资料”可维护昵称、电话和密码。统计口径和操作说明见 [营业统计、图片上传与账户维护](statistics-images-account-guide.md)。

`npm run test:e2e` 自动启动 3002/5174 测试服务，使用独立 MySQL 测试库，当前共 38 项：顾客 10 项、原商家 9 项、缺陷回归 5 项、注册/超时 3 项、查询/提醒 4 项、统计/图片/账户 7 项。覆盖权限、菜品分类管理、接单配送完成、拒单退款、冲突与响应丢失恢复、分页、会话、查询筛选、提醒去重与恢复、统计口径、上传预览保存和顾客展示、资料回显及结算默认值、修改密码与旧会话失效，以及 375px/桌面布局。真实 MySQL API 共 40 项，另覆盖日期边界、全部待接单快照、聚合金额、图片格式/大小/路径、资料字段隔离及改密竞争。

测试启动会清理 `TEST_DATABASE_URL` 对应测试库中的点餐业务记录，不操作应用库。浏览器测试和 `npm run test:api` 共用测试库，顺序执行。页面截图输出到忽略提交的 `test-results/admin-menu-mobile.png` 和 `test-results/admin-orders-desktop.png`。

查询与提醒的截图为 `test-results/admin-search-alerts-mobile.png`、`test-results/admin-search-alerts-desktop.png`。
