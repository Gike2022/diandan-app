# 点餐系统第一阶段：MySQL 与后端接口

## 已确认的目标

用于课程设计和作品演示。用户已确认保留现有 React + TypeScript 前端，采用 Node.js + TypeScript + Express + MySQL，先交付数据库和后端接口。顾客页面与商家页面的联调属于下一阶段。

## 范围

- 在 `server/` 中建立独立的 Express 5 服务，使用严格 TypeScript。
- 用 mysql2 参数化 SQL、版本化 SQL 迁移和初始化脚本管理 MySQL，便于检查课程数据库设计。
- 用户注册、登录、退出和当前账号；顾客与管理员两种角色。密码用 Node.js scrypt 哈希，随机访问令牌仅以 SHA-256 摘要保存在数据库中。
- 公开分类和菜单查询；管理员分类和菜品维护，包含排序、停售和售罄。
- 创建订单、本人订单列表与详情、取消订单；管理员查询订单并按合法流程更新状态。
- 明确标记的模拟支付成功/失败接口和支付记录，默认仅用于开发演示，不对接真实支付。
- 管理员订单汇总接口。
- 导入现有 5 类、15 道菜品，保留 `h1` 等菜品 ID，提供显式初始化的演示账号。

## 数据模型

`users` 保存账号、密码哈希和角色；`sessions` 保存令牌摘要及有效期；`categories`、`dishes` 保存菜单；`orders` 保存顾客、收货信息、金额和订单状态；`order_items` 保存菜品 ID、名称、图片及单价快照；`payments` 保存模拟支付尝试与结果。外键、唯一约束、检查约束和查询索引写入 SQL 迁移。

金额统一使用整数分。包装费沿用现有前端的每份 50 分。前端只提交菜品 ID、数量与收货信息，后端读取菜品价格、校验售卖状态并重新计算总额。

## 关键业务规则

- 注册固定为顾客，管理员只能通过初始化脚本创建。
- 用户仅能读取和操作自己的订单；商家接口由服务端校验管理员角色。
- 下单在同一事务中写入订单和明细。`Idempotency-Key` 在每个用户范围内唯一；相同请求重试返回原订单，换内容重用同一键返回冲突。
- 订单流程为 `pending_payment -> pending_acceptance -> preparing -> delivering -> completed`；顾客只能取消未付款订单。管理员可以拒绝已付款待接单订单，此时模拟退款与取消在同一事务中记录。
- 支付状态单独保存为 `unpaid / paid / refunded`。模拟付款、取消、商家状态变更对订单加行锁，防止并发重复付款及非法状态覆盖。支付失败保留订单待付款。
- 菜单变更不改写历史订单快照；已被订单引用的菜品采用停售操作，避免破坏外键与历史记录。
- 普通业务错误统一返回 `{error: {code, message, details?}}`；参数、JSON、权限、找不到资源和状态冲突使用不同 HTTP 状态码。

## 工程与运行

- 前后端依赖及输出目录分别管理，保留现有前端命令。
- `.env.example` 只包含演示配置，真实 `.env` 和本地数据库文件忽略提交。
- API 默认监听本机，允许的前端来源通过环境变量配置。
- 现有 MySQL 实例需要密码，不猜测密码或修改其数据。增加可选的项目本地 MySQL 启动脚本，使用本机已安装的 mysqld，在独立数据目录和端口 3307 上运行。
- 初始化菜单可重复执行，不覆盖管理员已经修改的菜单和密码。

## 验收

在真实 MySQL 上验证迁移、重复初始化、登录与权限、菜单售罄、金额重算、订单快照、事务回滚、重复及并发下单、模拟支付重试、取消/支付竞争、商家状态变更及历史持久化。后端类型检查、构建和集成测试必须通过。前端类型检查与构建作为兼容性检查，构建产物写到临时目录以保持现有 `dist/`。
