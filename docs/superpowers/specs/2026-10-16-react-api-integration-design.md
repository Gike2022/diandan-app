# 第二阶段：现有 React 页面接入点餐 API

## 用户已确认的范围

保留现有 React 前端、粉紫色主题、星空背景、移动端卡片布局及动效，完成登录、动态菜单、下单、模拟支付、历史订单查询。后端业务规则沿用第一阶段，本阶段不增加商家管理页面。

## 页面与数据流

- 增加同风格登录页 `/login`，登录成功返回原页面。刷新时用 `/auth/me` 验证会话；过期重新登录，网络故障可重试。退出清理个人查询缓存。
- 首页读取 `/categories` 和完整分页菜单，沿用现有分类滚动与菜品卡片，增加加载、空菜单、失败及重试反馈。
- 购物车继续使用 React Context，浏览器缓存仅用于购物车恢复。购买数量限制与后端保持一致，金额按整数分计算。
- 结算页提交菜品 ID、数量、联系人、手机号、地址、备注和模拟付款方式。先创建订单，显示后端确认的金额，再进入付款操作。提交前保存本次幂等键与请求体，网络结果不明时用相同请求重试，刷新后仍能确认原订单。
- 增加 `/orders/:id` 订单详情与模拟支付页。清楚标记模拟付款成功/失败，失败可重试；已付款不能重复付款。未付款订单可取消；详情定期从后端读取实际状态。
- 历史订单从 `/orders` 分页查询，以登录用户区分缓存。展示状态和金额，可继续支付、查看详情；“再来一单”重新查询当前菜单，使用真实 dishId、最新价格和图片，售罄或停售时给出反馈。
- 开发和预览通过 Vite `/api` 代理连接后端；部署可以配置 `VITE_API_BASE_URL`。页面内部导航保持 BASE_PATH 兼容。

## 实现约束

使用已有 TanStack Query 管理服务端状态，原生 fetch 统一处理 JSON 错误、超时、取消与 401；不新增另一套客户端状态管理。React 18 下使用普通 hooks，不使用 React 19 专有 API。新增表单带可见标签，提交按钮有忙碌状态，错误可读且不清空表单。真实收款码不再出现在模拟付款流程中。

## 验证

在独立测试库上通过自动化浏览器测试覆盖匿名浏览、登录错误、登录后返回、动态菜单、下单及手机号保存、模拟失败后重试、成功后刷新、历史记录、继续付款、再来一单、退出及会话失效、重复提交重试、接口错误反馈。检查移动端视口与现有风格一致；后端原有集成测试及前后端构建通过。
