# 营业统计、图片上传和账户维护

继续已授权的单店课程演示系统开发，交付现有 React 网站内的页面，保持粉紫星空、圆角卡片和既有认证/交易流程。无需引入外部托管或修改演示账户密码。

## 营业统计

新增管理员页面 `/admin/statistics` 和受权限保护的 `/api/admin/statistics`。默认最近 7 天，支持北京时间自然日范围，最多 92 天。统一按下单时间筛选订单群组，包含开始和结束日。营业额为此群组中当前已完成且仍已付款的订单总额，包含包装费；不计待付款、制作配送中和取消退款订单。退款额为群组内成功退款记录金额，不按退款发生日期另划群组。热门菜品按已完成已付款订单明细销量排名，金额不含包装费，菜品名称采用当前目录名称，价格使用历史明细快照。

页面从摘要到明细展示营业额、完成单量、总单量、每日营业额趋势、各状态数量、退款金额和热门菜品。日期筛选作用于全部区域，展示查询时间、指标口径，空数据为真实零值。多条聚合查询在同一只读快照事务执行，避免一笔订单的多条明细重复放大订单金额。图表使用项目原有风格的 SVG，并提供对应数据表供精确查询和无障碍阅读。

## 图片上传

新增管理员上传接口，使用图片二进制请求体，最多 5 MiB，支持 JPEG/PNG/WebP。服务端识别真实格式、限制像素数（2500 万），使用 sharp 解码并统一转换为最长边 1600px 的 WebP；拒绝损坏内容、SVG、动画和伪装文件。按输出内容摘要保存，原子写入，重试可复用相同文件。上传目录独立于代码和数据库，默认 `.local/uploads/menu`，可配置。测试使用独立临时目录。

图片经公开的 `/api/uploads/menu/<摘要>.webp` 只读地址展示，严格限制文件名。目录不能列举或读取其他路径。已有 HTTP/HTTPS 图片地址保持可用；历史订单继续保存原图快照，替换菜品图不会删除历史文件。编辑器支持选择、上传反馈和预览，上传完成后保存菜品才生效，上传失败不清空旧图或其他输入。

## 个人资料与密码

新增受登录保护的 `/profile`，从原有页头提供入口，顾客及管理员均可使用。昵称和联系电话可保存，电话可清空；用户名和角色只读。资料只修改当前用户，接口严格拒绝角色、用户 ID 等额外字段，结算继续使用最新昵称/电话作初始值。

密码表单输入原密码、新密码及确认新密码。新密码维持 8–128 字符规则且不能与原密码相同，密码不缓存到浏览器存储。服务端核对原密码，使用现有 scrypt 保存新摘要，在同一事务撤销全部旧会话并为当前页面签发新会话。原密码错误返回 400，保留登录。登录和改密对用户行加锁并重新核验会话，防止旧密码登录与改密竞争后产生有效旧会话。成功保持当前页面登录并清空密码输入，其他旧会话下次请求失效。新增密码接口有限流。

## 验证与范围

在独立 MySQL 测试库验证聚合口径、自然日边界、退款、失败支付、历史价格、权限、空数据、范围限制；验证上传类型、大小、真实内容、公开读取及重试；验证资料隔离、参数拒绝、改密原密码校验、全部旧会话失效和竞争。浏览器验证筛选、失败重试、上传预览/保存/顾客展示、资料回显/刷新/结算默认值、改密后新旧密码登录、管理员使用及窄屏/桌面布局。顺序重跑全部 API 与浏览器测试，完成类型检查、构建与页面截图检查，再更新说明并重启本地服务。

本次不新增收货地址簿、头像、找回密码或真实支付。已有数据库字段足以实现本次功能，无需改写现有 SQL 迁移。
