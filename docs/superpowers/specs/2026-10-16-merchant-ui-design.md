# 商家管理页面设计

## 范围与实现方式

延续已确认的单店课程演示方案。用户本次明确要求实现商家页面、菜品管理、接单和状态更新，并保留风格。采用现有 React 项目内 `/admin` 路由，复用账号、API 客户端、TanStack Query 与主题；独立后台项目会增加重复的鉴权和构建配置，当前不需要。已有数据库和后端业务规则保持一致。

## 页面

- `/admin`：订单管理，默认待接单，状态筛选、分页、手动刷新及 5 秒自动刷新。展示订单号、时间、菜品、收货信息、备注、支付和金额。待接单可接单或填写原因拒单，制作中可开始配送，配送中可确认完成。未付款、已完成及已取消订单只读。拒单通过确认对话框并标记模拟退款。
- `/admin/menu`：菜品管理，搜索、分类筛选及分页。新增/编辑表单覆盖名称、分类、元单位价格、描述、HTTP(S) 图片地址、排序、售罄及上架状态。价格校验到分，提交整数分。上/下架及售罄快速操作复用 PATCH，保留历史订单引用，不做物理删除。分类从后台分类接口读取，包含停用标记，便于解释菜单隐藏原因。
- `/admin/categories`：用于菜品管理的分类维护：新增、编辑名称和排序、启停，提示停用会隐藏分类中的菜品。

商家布局沿用粉紫、星空和圆角卡片，手机单栏、桌面适度加宽并使用卡片网格，提供订单/菜品/分类导航与返回顾客菜单。表单用已有 Radix Dialog，标签可见、错误保留输入、提交禁用防重、移动端对话框可滚动。新增页面避免不必要入场动画。

## 权限与数据同步

使用现有登录页，安全返回路径允许 `/admin` 及明确的管理子路由。客户端角色门禁加服务端 requireAdmin；顾客展示无权限页面，不请求管理数据。管理缓存以 admin 前缀和用户 ID 区分，退出、账号切换清除。管理员首页入口可见，管理页面提供退出。

菜品/分类写入后刷新管理列表、分类与公开菜单缓存。订单操作先取消旧查询，再写入响应和刷新列表/汇总/顾客订单缓存；409 等失败显示可读信息并重新查询当前状态，避免前端假成功。轮询与手动刷新不覆盖正在提交的表单。

## 验收

用独立 MySQL 测试库运行浏览器测试，覆盖未登录返回、普通顾客拦截、管理员入口、菜品新增编辑（含精确分）、筛选、售罄和上下架、分类启停、接单到完成、拒单和模拟退款、其他终端状态冲突与失败重试、会话失效以及移动/桌面布局。原有顾客 10 项和后端 21 项测试回归，前后端类型检查和构建通过。应用库不写测试订单，不修改原主题 CSS、星空组件与已跟踪的 dist。
