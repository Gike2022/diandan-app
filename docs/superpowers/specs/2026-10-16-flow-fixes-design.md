# 五项流程缺陷修复

用户已要求修复上一轮检查中确认的五项问题，保留页面风格并重跑完整流程。沿用上一轮的复现证据和修复建议，不增加新业务页面。

1. 分类、菜品新增 version 字段；编辑表单提交改动字段和 expectedVersion，数据库以单条条件 UPDATE 检查版本并递增。旧版本返回 409，表单保留输入并提示重新打开最新记录，防止覆盖价格或售罄。旧 API 调用不带版本仍可按字段更新；商家 UI 始终带版本。
2. 菜品与分类新增支持 Idempotency-Key，按用户、资源类型和键持久化请求摘要及资源 ID；同键同内容返回已有资源，换内容返回 409。请求记录与资源创建共用事务。管理表单在发送前持久化请求体和键，模糊网络结果复用原请求，刷新后可恢复；成功或明确拒绝后清理。
3. 购物车保存在带 revision 的共享快照中，兼容旧购物车并监听跨标签页更新。新订单的幂等键由共享 revision 派生；每个结算仍保存自身请求快照，断网可重试。同一购物车并发结算最多创建一笔订单；不同信息复用键时明确拒绝。快照同时保存已扣除的结算标记，避免重复响应二次扣购物车数量。
4. 商家订单总页数减少时，将当前页约束到有效范围，重新加载该页。
5. mysql2 的解析时区与每条池连接的 MySQL 会话时区统一 UTC，确保已有自动更新时间字段正确写入。原迁移不改动。不推测性批量修改缺少来源依据的历史时间。

## 验证

将本地五个复现脚本转为正式回归断言，先确认修复前失败，再逐项执行。补后端并发创建、幂等内容冲突、条件版本更新和 UTC 会话测试。顾客与商家既有 19 项浏览器测试、后端既有 21 项集成测试、前后端类型与构建必须通过。所有业务测试使用独立测试库，顺序执行避免重置冲突；应用库只执行增量迁移。主题 CSS、星空组件和原 dist 不变。
