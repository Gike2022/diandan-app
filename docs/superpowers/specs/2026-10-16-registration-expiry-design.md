# 用户注册与未付款订单超时

用户要求补上注册和未付款超时取消，保留现有风格，并明确选择 15 分钟付款时限。

## 注册

新增 `/register`，复用现有粉紫卡片和表单样式，包含账号、昵称、可选联系电话、密码与确认密码。注册调用既有接口，账号转小写，固定顾客角色，不支持自选管理员。前端校验重复密码与输入规则，后端最终校验账号唯一性；失败保留输入并聚焦错误。成功采用返回会话自动登录，保留购物车并安全返回 next 指定页面。登录与注册可互相切换，next 沿用现有白名单。

## 订单付款时限

新增迁移保存每笔订单的 `payment_expires_at`，老记录按创建时间加 15 分钟补齐并保留原更新时间；新订单由服务器读取配置（默认 900 秒）写入截止时间。配置变更只影响新订单，幂等重试保留原截止时间。增加状态/支付状态/截止时间索引。

API 进程启动及每 30 秒运行一次后台扫描，以条件 UPDATE 将到期、待付款、未付款订单取消，原因为“付款超时自动取消”，支付状态保持 unpaid，不生成退款。进程重启补扫，不依赖页面打开。查询订单前也执行补扫，及时展示状态。

付款事务取得行锁后，用数据库当前 UTC 时间再次检查截止时间；到期时提交取消再返回 409 PAYMENT_EXPIRED，不能通过回滚恢复待付款。后台扫描与付款竞争时，以行锁和条件更新保证最多一个有效结果。已付款订单不受超时扫描影响。停止服务时先停止扫描并等待当前扫描结束，再关闭连接池。

详情页使用服务器时间计算剩余秒数，以本地单调计时更新倒计时，避免依赖用户设备时钟。倒计时结束禁用付款并刷新真实状态；历史和详情展示自动取消原因。主题 CSS、星空与原有页面布局保留。

## 验证

真实 MySQL 测试默认截止时间、配置范围、幂等重试不续期、超时取消、未到期/已付款不受影响、支付拒绝、行锁等待跨截止时刻、付款与扫描竞争、启动补扫和停止任务。浏览器测试注册错误、重名、自动登录与结算返回，以及倒计时到期、历史查询和不打开页面时自动取消。完整顾客/商家/既有回归测试、前后端类型检查和构建通过。测试库顺序运行，应用库只做增量迁移。
