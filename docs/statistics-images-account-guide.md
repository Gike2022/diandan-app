# 营业统计、图片上传与账户维护

沿用现有粉紫星空主题、圆角卡片和手机/桌面布局。先启动前后端，演示账号见项目根目录的 [登录账号说明](../登录账号说明.md)。

## 查看营业统计

管理员打开 [营业统计](http://127.0.0.1:5173/admin/statistics)，也可在商家导航中进入。

1. 默认查看近 7 天，可点击今日、近 7 天、近 30 天，或填写开始/结束日期后点击“查询统计”。最大范围为 92 天，日期按北京时间计算，包含结束日期整天。
2. 上方显示营业额、已完成订单数、订单总数；下方为每日营业额、六种订单状态数量、模拟退款金额和热门菜品。点击“查看每日明细”可看精确数值。
3. 页面每 30 秒重新查询，点击“刷新统计”可立即更新。同一范围再次点击查询也会重新汇总。

营业额仅计算所选日期内下单、当前已完成且已付款的订单，包含包装费。待付款、未完成和已退款订单不计营业额。热门菜品使用历史订单明细价格，金额不含包装费；菜品名展示当前名称。退款金额属于所选日期内下单订单的成功模拟退款，统计范围不是退款发生日期。所有金额均来自演示交易。

如果查询没有订单，页面显示真实零值；查询失败可重试，日期错误会保留输入。

## 上传菜品图片

管理员打开 [菜品管理](http://127.0.0.1:5173/admin/menu)，新增或编辑菜品：

1. 点击“上传菜品图片”下的文件选择控件，选择本机 JPG、PNG 或静态 WebP，单张最多 5 MB，像素数最多 2500 万。
2. 上传时显示进度状态并暂时禁用保存；完成后显示预览，图片地址自动填入。也可继续填写原有 HTTP/HTTPS 图片地址。
3. 点击“保存菜品”后，顾客菜单使用这张图片。上传失败会保留原图和其他输入，可重新选择文件重试。
4. “移除图片”清空当前菜品的图片字段，点击保存后生效。旧文件保留，历史订单继续显示下单时的图片。

服务器将图片转换为 WebP 并限制最长边为 1600px。上传文件默认保存在项目 `.local/uploads/menu`，通过 `/api/uploads/menu/文件名.webp` 展示。文件存储不依赖 `dist` 构建目录，因此重新构建不会覆盖上传图片。

## 个人资料与修改密码

顾客和管理员登录后，点击页头的人物图标“个人资料”，或打开 [个人中心](http://127.0.0.1:5173/profile)。

- 个人资料：可修改昵称和联系电话，电话可清空；账号和账户身份只读。保存成功后刷新仍会保留，下次结算使用最新昵称和电话作默认值，已有订单收货信息保持其历史记录。
- 修改密码：填写原密码、新密码及确认新密码。密码为 8–128 个字符，新旧不能相同；“显示密码”可切换可见性。原密码不正确时保留登录和表单，便于修正。
- 修改成功：清空密码输入框，当前页面使用新会话继续登录，所有旧会话失效。再次登录使用新密码；同浏览器其他标签页同步新的登录令牌，其他旧会话下次请求时要求重新登录。

项目不会自动更改网站演示密码。若你自行修改了演示账号密码，账号说明中的初始密码不再适用于该账号。

## 部署与备份

`server/.env` 可配置 `UPLOAD_DIRECTORY`（绝对路径或相对后端运行目录的路径），默认 `../.local/uploads/menu`。目录需要后端进程可读写。部署时除了备份 MySQL，也需要备份整个上传目录，两者共同恢复，才能保留历史菜品和订单图片。

前端默认经 Vite 的 `/api` 代理加载上传图片。正式使用独立前端时，应按已有部署说明设置 API 地址、CORS 和反向代理；前端的 `VITE_API_BASE_URL` 为绝对地址时，上传图片展示也会使用对应后端地址。仅部署前端静态文件不能接收上传或运行后端。

## 测试

先执行 `npm run test:api`，结束后再执行 `npm run test:e2e`，两者共享独立测试库，不能同时运行。当前新增 7 项 MySQL 集成测试和 7 项浏览器测试，总计 40 项接口、38 项浏览器测试。另执行前后端类型检查与构建。

上传测试使用单独临时目录；账户修改、改密码、菜品及订单测试仅写测试库，不修改应用库现有演示密码。截图为 `test-results/statistics-mobile.png`、`statistics-desktop.png`、`profile-mobile.png`、`dish-upload-mobile.png`。
